# FreeComplete

FreeComplete is an original, free, on-device macOS writing assistant. It bundles a public Gemma 4 E2B **base-model i1-Q4_K_M** GGUF and a pinned llama.cpp helper. Autocomplete uses raw token distributions and bounded ranked search, not chat replies. No Ollama process, account, cloud API or subscription is required. The public GGUF differs from Cotypist's installed file. FreeComplete uses no Cotypist code, assets, installed weights or private profiles.

## Build and run

Requires macOS 14+ on Apple Silicon, Swift 6.2, CMake, Apple command-line tools, and about 9 GB of free space during packaging. The build script downloads a hash-checked [public base-model GGUF](https://huggingface.co/mradermacher/gemma-4-E2B-i1-GGUF) and Apache-2.0 license to a build cache, fetches pinned llama.cpp source, applies three original patches in byte-prefix, probability and shared-prompt admission order, builds a statically linked helper, packages the model and notices, and signs the app. Signing uses `FREECOMPLETE_SIGN_IDENTITY` when set. Otherwise it uses a code-signing identity named `FreeComplete Local` if one is in your keychain. If neither exists, it uses an ad-hoc signature.

```sh
./scripts/build-app.sh
open dist/FreeComplete.app
```

The app is at `dist/FreeComplete.app` (about 3.4 GB). For distribution to other Macs, use an appropriate Developer ID signature and notarization. An ad-hoc signature changes on every build, so macOS drops the app's Accessibility approval and Keychain history access after each rebuild. A self-signed `FreeComplete Local` code-signing certificate gives a stable, certificate-based designated requirement for local use; local and ad-hoc signatures skip hardened runtime and Apple timestamping. After the first switch to a new signing identity, reset the old approval once (`tccutil reset Accessibility app.freecomplete`) and grant it again. The bundled model is Apache-2.0 licensed; third-party notices are in `Licenses/` and in the app's Resources. The runner binds to `127.0.0.1`, uses a fresh per-launch authentication key, starts lazily at first completion, and stops with the app.

Runtime source/build caches include the pinned commit and patch-content digest. A changed patch uses a fresh cache instead of modifying an older release's source tree. The model cache is shared. Old source/build caches remain on disk for manual cleanup; the build never deletes them automatically.
The build validates the complete ordered patch tree before reusing a source cache. It reuses an exact fully patched cache and rejects staged, untracked or unexpected source changes rather than overwriting them.

## Use

The app has a **FC** menu bar entry with Open, Pause/Resume and Quit actions, plus a Dock-accessible settings window with Home, Writing, Apps and Privacy tabs. The entry shows how many completions you have accepted (for example `FC 42`); each Tab, grave, alternative or rewrite acceptance counts once, and its menu also shows the total accepted words. Menu bar managers such as Ice may hide the FC item; click the Dock icon to reopen settings. Home has a **real model** test editor. The first generation loads the model and can take longer. For suggestions in other apps, grant FreeComplete Accessibility access in macOS System Settings using the explicit button in Home if it is not already granted. The app reads cursor context through Accessibility, skips secure text fields, and verifies focused target and text again before insertion. Some apps do not expose the necessary editable-text Accessibility attributes and will not show suggestions. Apps that expose only an entire AX value may require reading it to extract the bounded cursor window.

Continuations appear inline as gray text right after the caret, in the field's own font scaled to its line height. Only words that fit inside the field are shown, so Tab and grave accept exactly what is visible; when the caret is at the right edge, the text starts on the next visual line. Alternatives, synonyms and corrections still use a small labelled panel. While a suggestion is visible, FreeComplete generates what follows it, so accepting the last word continues straight into the next suggestion. A Tab or grave pressed before the next part appears is held and applied when it does, instead of typing a tab character. The model loads when completions start, not at the first keystroke.

Electron apps such as Slack, Ferdium, Discord and VS Code hide their text fields from Accessibility by default. When one of them comes to the front, FreeComplete sets Electron's documented `AXManualAccessibility` switch on it, which makes the app build its accessibility tree, and then reads the field again. Other apps ignore the attribute.

Opt-in screen context reads the screen column around the focused field: the conversation or document you are replying to, not sidebars or the menu bar. It uses accurate OCR, removes the field's own text, chat timestamps, number-only and low-confidence fragments, rebuilds visual lines in reading order, and keeps the 1,200 characters nearest the caret. Recognition runs in the background (about 0.65 s on a test screen) and suggestions use the latest result, so they never wait for OCR. While the visible suggestion was built with screen text, the FC menu bar icon changes to an eye. The Home tab's **Screen context** section shows the source app, the capture age, and the exact text the model received.

- **Tab:** accept the next word (unless Option is held).
- **` (grave):** accept the entire suggestion.
- **Esc:** dismiss temporarily.
- **Control+Option+`:** request three alternative next words, then press **1–3** or Tab to insert one. All three fill the same slot: either new next words, or endings for the word being typed. Choices that start with brackets, quotes or markup are skipped.
- Select one word and press **Control+Option+S** for a contextual synonym. Select text and press **Control+Option+C** for a spelling/grammar correction. Tab or grave replaces the selection.

Settings include a global enable switch, maximum suggestion length, spacing, global instructions, per-app and per-website enable/learning/instructions, and optional screen OCR or clipboard context. Website rules use HTTP(S) document URLs exposed through Accessibility, including known enclosing frames; a parent-domain exclusion cannot be overridden by a subdomain. If a web field's outer URL cannot be established, configured suggestion and recording exclusions fail closed independently. Observed app and website names appear in settings only for this session; only rules you configure are saved. Screen OCR requires separate Screen Recording permission, captures the display containing the caret and excludes windows belonging to excluded apps; it is suspended entirely while any website has an exclusion so another visible browser window cannot bypass it. Clipboard and screen text are used only when enabled, on this Mac, and not saved; concealed/transient clipboard items are skipped. macOS may ask before clipboard access. Writing history is off by default. With explicit opt-in, short samples from accepted completions are AES-GCM encrypted with a Keychain key; an additional off-by-default switch also records monitored writing after a pause or when leaving a field. Text under 40 characters is skipped. History is scoped by app and website, capped at 2,000 samples of at most 200 characters, and clearable from Privacy. Vocabulary influence can be turned off or adjusted, and app/website recording can be disabled independently. The helper is never given an external network host.

Password managers (1Password, Bitwarden, Apple Passwords, Dashlane, LastPass, Keeper, Proton Pass, KeePassXC) and terminals (Terminal, iTerm2, Ghostty, Warp, kitty, Alacritty, WezTerm) start with suggestions, learning and screen capture off. Enable one in the Apps tab to override the default.

### Suggestion quality

Autocomplete keeps bounded before-caret writing separate from prompt references. It reconstructs up to five eligible source-tail tokens without changing typed bytes, then ranks a frontier of at most nine sequences. A separate unmasked model likelihood penalizes improbable prefix reconstructions; post-prefix ranking sums retained log probabilities. A pending prefix uses a relative probability gate instead of the ordinary 0.05 gate. Alternatives come from distinct ranked next words; selected-text rewrites use separate raw tasks. Top-twenty candidate retention, beam width and complete-word delivery are explicit limits and policies, not identical Cotypist behavior.

Continuation uses a neutral, descriptive prompt: a short preface, labelled optional context (app, website, vocabulary, screen, clipboard, text after the cursor), the writer's preferences nearest the writing, then the raw writing last. It does not use chat-style instructions. With the public base model, instruction framing gave about a quarter of the probability to placeholder tokens such as `...` and `[`, so the generic “The next step for this project is” returned ` to...`. Search runs one generation round per allowed word (four by default), after any source-prefix reconstruction, and delivers only confirmed words. A suggestion must contain a letter or digit, and suggestions appear only when the caret is at the end of its line.

The prompt uses the last 2400 characters before the caret and the first 900 characters after it. Opt-in screen and clipboard references each use their first 1200 characters. These are deliberate context windows, not complete-document coverage. Selected correction text and user instructions are not shortened by these windows.
Focused app metadata uses the first 100 characters of the app name and 200 characters of the app identifier. Learned vocabulary uses up to 200 characters per strength level, with an 800-character ceiling.

Prefix-finishing tokens pay their entire original likelihood, including any new suffix. Pending and prefix-complete paths share a bounded beam, so tokenization and pruning can affect which completion survives. A malformed or missing likelihood rejects the whole prefix distribution. The bounded regeneration budget can also end before an alternate byte-tokenization finishes. These are explicit limits, not fallback scores or complete search coverage.
While generation is active, opening brackets or opening quotation marks do not confirm a finished word. A colon after a digit also remains unfinished because a time or ratio can continue. Whitespace and EOS still confirm literal punctuation; these boundaries do not filter citations or repair model meaning.
Fallbacks retain only confirmed text and use the evaluated branch's current score, not its earlier checkpoint score. Budget, suppression and terminal fallbacks therefore cannot revive a stale higher rank and violate the settled-result bound. Below-limit checkpoints do not compete immediately with their longer descendants.

Search batches branches with the same remaining byte constraint. The runtime prepares the transient vocabulary mask once per request, evaluates the common token prefix once through llama.cpp's existing parent/child task owner, and maps each indexed probability row back to its original branch. Nine slots share one 8192-token KV pool, not nine independent contexts. Each request group owns the pool until all its branches release it, so an overlapping correction or replacement request waits instead of exhausting shared memory. Full sliding-window KV storage permits prefix sharing without changing model attention. Admission includes shared source, separate tails and output positions. The strict score bound stops only when unfinished paths cannot beat the requested completed results; equal-score paths remain eligible.

Screen OCR, clipboard context and encrypted writing history remain off until you opt in. A fragment such as “The next step for this project is” supplies no project facts, so generic suggestions remain possible. Optional screen context and global/app/website instructions can supply relevant facts, but the current model can ignore explicit instructions or prefer conflicting reference text. Learning contributes frequent vocabulary terms, not a derived tone/style profile. REA resolves ordinary cumulative ranking, zero default position bias, token-round stopping and coarse first-byte prefix groups. Exact target weights, adaptation tables, the active single-space bucket setting and winning UI selection remain unknown. FreeComplete's raw prefix likelihood remains an original policy, not the target's bucket-normalized score. See [PLAN.md](PLAN.md) for evidence and exercised results.

Corrections encode the complete selection as a JSON string, separate from prompt labels and stop markers. Independently authored editing pairs demonstrate minimal edits while preserving literal labels, repeated text, language, whitespace and Unicode spelling. The runtime accepts only a complete JSON-string replacement, preserves the selection's leading/trailing whitespace, and does not offer an unchanged source. The 8192-token context limit includes the full instructions, selected text and output reserve; oversized requests fail explicitly rather than silently deleting input. These checks prevent representation truncation, not model mistakes. Review a proposed correction before accepting it.

Real production diagnostics stop the tested year and compound chains and preserve `determinis` and `extraor` completion. Corrections preserve tested padding, repeated text, tabs, blank lines and decomposed Unicode, but do not reliably fix every error. Some literal-label/tabbed samples retain one agreement error; a French sample retains an adjective agreement error; Japanese past/future errors can remain unchanged. A longer repeated quoted-path selection makes the model repeat beyond the source and reach its output limit without a complete JSON string; FreeComplete rejects the result and preserves the selection. French continuation instructions are still ignored, Japanese continuations can end at an incomplete grammatical span, and alternatives remain weak. General quality and Cotypist parity are not established.

## Checks and limits

```sh
./scripts/test-prediction.sh
swift build -c release
```

The test runner checks bounded multi-token source rewind, exact Unicode bytes, prefix/ordinary Float32 gate boundaries, production candidate decoding and validation, raw prefix consumption with surplus preservation, phase-aware ranking, stable byte-constraint grouping, indexed response mapping and rejection without partial mutation, aggregate context capacity and overflow, raw partial-word and multilingual word-boundary insertion, alternative identity/spacing, punctuation, correction JSON completeness and selection whitespace, synonym selection eligibility, website parsing, nested-frame exclusions, unknown-site fail-closed behavior, and absence of unconsented context. The built-in editor exercises bundled model generation without Accessibility. Actual cross-app observation/insertion and screen OCR require the corresponding macOS permissions and separate verification. [PLAN.md](PLAN.md) distinguishes earlier exercised UI behavior from current-build verification.
